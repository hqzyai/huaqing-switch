# HQ 模型限制与用量统计

## 模型限制填写

连接表单的上下文和单次输出上限单位均为 **Token**，保存完整的正整数，不填 `M`、`k` 后缀，也不是字符数或字节数。

| 服务商标注（十进制） | 表单填写  |
| -------------------- | --------- |
| 上下文 1M            | `1000000` |
| 最大输出 393k        | `393000`  |

若服务商给出精确值，例如 `1048576` 或 `393216`，按精确值填写。上下文允许 1024–2000000 Token，输出至少为 1 且不能超过上下文。本地设置用于向 HQHarness 声明预算和限制请求的最大输出，不会增加服务商实际支持的容量或账户额度。

不要把界面的约写作为精确容量。例如 DeepSeek V4.1 Flash 的官方最大输出标为 384K，API 文档明确为 `393216` Token，应填写 `393216`，而不是按约写的“393k”填 `393000`。通过第三方服务接入时以该服务的限制为准。参见 [DeepSeek 模型规格](https://api-docs.deepseek.com/quick_start/pricing/)及[最大输出参数](https://api-docs.deepseek.com/api/create-chat-completion/)。

## 统计范围

0.1.1 起，侧栏提供独立的 **用量统计** 页面。它仅统计通过 Huaqing Switch 本机服务的 HQ 请求，不扫描其他客户端的历史会话，也不读取供应商账单或账户余额。旧版本未记录的历史 Token 无法补算。

页面提供今天、最近 7 天、最近 30 天和全部时间，可按连接和模型筛选；显示请求结果、输入/输出 Token、缓存 Token、按连接与模型的分组以及分页请求明细。日期按本机日历计算，查询使用起点包含、终点不包含的时间范围。统计保存在本产品 SQLite 数据库中，重启后仍可查看；连接改名、修改模型或删除时，既有请求保留发生时的连接与模型快照。

## 数据含义

- 用量来自上游返回的 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages JSON / SSE 字段。使用量未上报与明确上报 `0` 分别展示，不根据文本长度估算。
- 输入 Token 包含缓存读取和缓存写入；缓存列是输入的组成部分，不能再加一次。总 Token 由可用的输入、输出数据计算，信息不全时不把缺失部分当成零。
- Anthropic 的原始输入字段不包含缓存。只有输入、缓存读取、缓存写入三个计数都明确返回时，才给出归一化的总输入；缺少缓存字段时保留部分用量状态，不猜测为零。
- 请求结果区分成功、失败、取消和中断。部分流式数据后发生取消或中断时，已返回的用量仍可能存在，但不能当成完整结算量。聚合页显示用量缺失及不完整的请求数。这里的成功表示 API 传输完成，不代表对话任务完成；非流式 HTTP 2xx 正常传输但返回无效 JSON 时仍原样透传，用量记为缺失，不代表 HQHarness 解析成功。
- 请求次数统计被本机服务接纳、且能够解析到已保存连接的推理调用，包括此后的参数校验和上游失败。鉴权失败、并发拒绝、配置存储不可读或连接已经删除/不存在的拒绝不写入统计。调用方自行重试会产生新的请求记录；Switch 不为统计而重放模型请求。连接页的“本次启动请求”是进程内计数，范围和生命周期与统计页的持久化历史不同。
- 费用、账户剩余额度和供应商最终结算不由这些 Token 计数推断；以供应商账单为准。

只保存统计必要的请求 ID、连接/模型标识、协议、时间、耗时、结果与用量，不保存 API Key、请求或回复正文、原始上游错误和请求地址。

用量观察器对单个 JSON 文档或 SSE 事件设 16 MiB 解析上限，超出后仍透传原始响应，已知用量最多记为部分用量；没有拿到字段时记为缺失。进程退出时尚未结束的记录在下次启动标记为异常中断，不虚构完成时间。

Chat Completions 流式请求在调用方未指定时补充 `stream_options.include_usage=true`，保留其他选项及显式 `false`。服务商不支持该选项而返回错误时，不自动重发请求。流中断可能收不到最终用量，不能据此认定没有消耗 Token。参见 [OpenAI 流式用量说明](https://help.openai.com/en/articles/10478918-reviewing-api-usage-and-costs)。

协议字段依据：[OpenAI Chat](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Anthropic 流式消息](https://platform.claude.com/docs/en/build-with-claude/streaming)、[Anthropic 缓存字段](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

## 0.1.1 本地验证

2026-10-27：前端全量 255 个文件、3231 项测试通过；最终 HQ 组件 13 项测试、类型检查、格式检查和渲染器构建通过。1000×640、1100×650、1920×1080 的浅深主题检查覆盖首屏 Token、表格局部横滚、键盘分页、日期选择和筛选重置，没有页面控制台错误。

HQ 原生 Rust 16 项测试覆盖三协议 JSON/SSE 分片、长文档尾部用量、解析上限、缺失与明确零值、部分错误、响应体未读取/部分读取后取消、HTTP 与流内错误、持久化恢复、分页筛选、存储失败不阻断推理及并发幂等。

另以实际编译的 macOS arm64 0.1.1 原生程序完成 9 个本地模拟调用：三协议分别使用 JSON 和流式响应，附加缺失用量、明确零值及重启后新调用。数据库恰有 9 条记录，重复上游响应 ID 未合并不同调用，原始响应字节不变、缓存未重复累加、鉴权失败未污染用量；删除测试连接并重启后历史不变。本轮临时进程与测试目录均已清理，没有调用付费模型。该结果不代替 Windows 安装后的验收。
