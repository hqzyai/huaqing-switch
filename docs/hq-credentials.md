# HQ 密钥与默认连接

Windows/macOS 客户端直接调用供应商。官方发布包预置默认阿里云连接，首次运行自动完成配置，不要求输入 API Key。默认模型为 `deepseek-v4.1-flash`，上下文限制为 1,000,000 token、单次输出限制为 8,192 token。用户可以在界面修改连接参数。

默认发布配置在 GitHub Actions Secret `HQ_SWITCH_BOOTSTRAP_BUNDLE` 中保管，经认证加密封装后进入原生程序，不进入前端脚本或源码。发布构建会验证配置的版本、格式、认证标签、供应商地址和模型；缺少有效配置则拒绝打包。普通开发和测试构建可以没有默认配置。

通用客户端必须能自行恢复默认凭据，封装也包含恢复所需材料。因此这项封装用于防止意外明文暴露，不是防逆向的保密边界；拥有安装包并分析原生程序的人仍可能恢复共享默认密钥。供应商平台的密钥启停和额度控制仍然有效。将真实供应商密钥留在远程服务端属于后续独立改造，本版本不改变客户端直连方式。

## 本机存储

HQ 数据库不再保存明文 `apiKey`。Windows 使用当前用户范围的 DPAPI；Mac 使用钥匙串中的独立主密钥和 AES-256-GCM。持久化保护不使用安装包内默认配置的恢复材料。密文认证绑定连接标识、供应商地址、协议、模型、名称、版本和预算等元数据，篡改或串换后会拒绝读取。

界面和普通管理接口只返回 `apiKeyConfigured`，不会返回已保存的密钥。编辑时留空保留当前值，明确清除则移除鉴权。密钥仅在原生进程中解密用于配置维护与模型调用，不回传界面。修改密钥仍更新连接版本，旧版本绑定的 Harness 会话需要刷新连接或新建会话。

复制数据库中的密文不能直接作为供应商 API Key 使用。系统管理员、控制同一系统账户的恶意程序或调试器仍不在这项静态存储保护的隔离范围内。Mac 的系统授权提示也不能绕过；使用 ad-hoc 签名的应用升级后，钥匙串可能要求用户重新授权访问。

## 升级与默认配置更新

启动时先迁移旧 HQ 连接，保持连接标识、选择和原有版本号；密文写入后清理 SQLite 旧页及 WAL。迁移中断会留下状态标记，下次启动继续清理；系统主密钥丢失、密文损坏、未知格式或非标准 settings 触发器会明确报错，不会清空配置或降级为明文。

每个发布默认配置版本只应用一次。首次升级可接管当前默认的同一阿里云工作空间连接；后续只更新已绑定的默认连接。其他连接，即使使用相同工作空间地址，也保留用户自己的密钥。已有模型、名称、预算和图片设置保留。新安装或空配置会新增预置连接；已有其他自定义连接且没有受管默认时，不额外注入模型或替换默认选择。用户随后修改或删除配置，普通重启不会反复覆盖。

## 备份和恢复

导出、数据库安全快照以及 SQL/二进制恢复均通过同一个密钥保护边界。受管 `backups/*.db` 中符合当前格式、归属和文件约束的旧 HQ 配置会迁移；未知文件、链接和未来版本文件不会被擅自重写。历史手工导出到其他位置的文件不在自动扫描范围，需自行安全保管或使用新版本重新导出。

加密备份依赖原系统账户的保护材料。跨设备或丢失系统密钥时，包含这些凭据的备份不能直接恢复；错误密钥的恢复请求不会覆盖当前数据库。需要跨设备部署时，应安装官方默认客户端并重新配置其他自定义连接，不应导出明文密钥。

Linux 服务端的共享实现使用单独挂载的 32 字节主密钥文件，不能与 SQLite 数据放在同一备份中。其部署要求见 [服务端说明](../server/README.md)。现有生产部署只有完成对应升级后才获得新存储保护。
