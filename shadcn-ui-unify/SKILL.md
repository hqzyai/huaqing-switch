# shadcn UI 风格统一

执行已有 React 项目的视觉迁移。用户的一次调用应推进到实现、检查和交付；不要只输出建议或组件清单。“一键”表示一次委托完成工作，不表示存在可以保证任意代码行为不变的机械替换命令。

## 范围与优先级

- 默认只处理当前项目的第一方 React Web UI；多个项目只处理用户指定的目录。保留用户现有未提交修改。
- 一致的视觉来自同一主题和组件规范，而不是每个项目重新选颜色。默认采用本技能的 `shadcn-neutral-v3`；用户指定的统一品牌/基准项目或固定旧版本优先。此规范由本技能定义，不是 shadcn 官方强制视觉标准。
- **业务与交互等价优先于替换率。** 能等价替换的通用组件使用官方 shadcn 源码；不能等价替换的复杂组件保留行为实现、统一外观，并明确列为兼容保留项。不得宣称这些组件已换成官方组件。
- **通用 UI 图标统一使用 Lucide 官方 `lucide-react`。** 不因已有其他图标库而整库保留；共享封装、官方组件内图标及页面图标均纳入迁移。品牌 Logo、用户内容与不可等价替换的专用图形按 [图标规范](references/icons.md) 处理；这不授权扩大为品牌重设计。
- **favicon 与控制台品牌 Logo 纳入完整迁移。** 本用户指定的品牌预设为 `hqzy-logomark-v2`：标签页与控制台品牌入口统一使用内置蓝色小标志 `assets/branding/hqzyai-logomark.svg`，不再使用文字字标。按 [品牌资源规范](references/brand-assets.md) 接入；明确属于其他品牌的项目沿用其品牌资产，局部图标/字体请求不附带更换品牌。
- 保留信息架构、页面区块及控件顺序、导航入口、响应式行为、文案和 i18n key；不套用官方 dashboard/sidebar 等整页 demo 重建产品。
- 保留 API/请求参数与时机、权限、路由参数、状态机、缓存、校验、持久化、业务计算和埋点。不趁机修复既有业务问题。
- 不升级 React、路由、状态管理、表单库或 Tailwind 大版本来适配最新样例。允许最小必要的 UI 依赖和构建接入；不替换项目架构。
- 不自动提交、推送或发布。普通检查、局部编辑和必要依赖接入持续执行，不每替换一个组件就请求确认。

## 1. 建立项目与行为基线

读取项目及目录级说明，检查包管理器/锁文件、React/框架版本、Tailwind/CSS 体系、组件封装、`components.json`、主题 provider、图标和现有检查命令。先判断实际应用根和共享 UI 包的归属。

建立简短迁移台账，放在项目已有任务记录处；没有约定时先用会话工作记录，不强行增加仓库文档：

| 页面/共享组件与调用点 | 现有行为及证据 | 官方目标/保留实现 | 验证路径 | 状态 |
| --- | --- | --- | --- | --- |

从路由、入口、懒加载页面和共享组件调用点盘点范围，包含权限分支、移动端和嵌套浮层。状态区分：待处理、已迁移且验证、兼容保留且验证、受阻未验证。不能只改首页/主题变量就声称全项目完成。

修改前运行相关既有检查并记录原有失败；可运行时，按项目规定启动，采集代表性页面的桌面/窄屏截图和交互基线。记录表单提交、弹窗关闭、键盘导航、状态持久化和路由跳转的实际行为。迁移涉及复杂交互时读取 [交互等价规则](references/behavior-contracts.md) 的相应类别。

## 2. 核对官方来源与兼容性

接入/新增组件前读取 [官方接入规则](references/official-integration.md)，再打开当前官方安装文档、目标组件页和对应源码。核对 React/Tailwind 兼容性、基础组件实现、依赖及许可。

- 新增 UI 组件源码只取自 shadcn 官方站及 `shadcn-ui/ui` 官方仓库；图标取自 Lucide 官方包。官网 Directory 中的第三方 registry 不因此成为官方组件。
- 已有 shadcn 项目保留本地配置、组件定制和底层实现系列。官方不同系列的 props 不能混用；按已安装源码处理，不能猜 `asChild`、`render` 或回调签名。
- 已有共享 Button/Input 等公共 API 时，在所属共享组件层接入官方实现；业务调用保持原接口。不要建立第二套并行基础组件系统。
- 未接入项目按对应框架的 Existing Project 流程做增量接入。CLI 会写配置、CSS 和依赖，先确认落点并审查 diff；不覆盖整份全局 CSS，不用 `--force`、`--overwrite`、`--all` 批量重装。
- 来源不可核实或当前版本不兼容时，继续可验证的本地主题/样式工作，具体组件标记受阻；不要编造官方实现或静默升级框架。

## 3. 固定跨项目的视觉基线

读取 [主题映射规则](references/theme-profile.md) 和 [默认主题数据](assets/neutral-theme.json)，再按下表定位规则。完整迁移覆盖所有适用类别；局部请求只读取有关部分，不因此扩大任务。

| 规范 | 何时读取 |
| --- | --- |
| [字体与形状](references/typography-and-shape.md) | 应用/检查字体、字号、字重、行高、圆角；包含自托管字体与许可证要求 |
| [间距、尺寸与状态](references/layout-and-states.md) | 应用设计基线时；包含密度、状态色、边框、焦点、阴影、层级与动效 |
| [Lucide 图标规范](references/icons.md) | 完整迁移或图标统一时；包含唯一通用图标库、尺寸、描边、语义映射、无障碍、导入方式与例外 |
| [favicon 与品牌 Logo](references/brand-assets.md) | 完整迁移或品牌入口统一时；包含内置 HQZY 蓝色 SVG、尺寸、静态资源路径、跨电脑分发、无障碍及验收 |
| [组件视觉规范](references/component-standards.md) | 迁移具体组件时读取对应类别；包含按钮、表单、导航、表格、浮层及反馈 |
| [覆盖与验收](references/acceptance.md) | 制定验证路径和最终验收时；包含响应式、可访问性、例外记录与重复调用规则 |

把同角色的值集中映射到项目 tokens/variants，迁移真实消费者，不只声明变量。沿用 Geist + Noto Sans SC、应用代码 Geist Mono 与固定排版；应用 UI 字体不因项目原来有另一套字体就自动保留。系统 fallback 只是容错，不能算字体已统一。

图标子规范固定为 `icons.profile = lucide-outline-v1`，与 `shadcn-neutral-v3` 一起记录；未记录该子规范的旧 v3 实施不视为已经完成 Lucide 统一。仅更新技能文件时不自动迁移项目；应用技能时才对实际调用点执行迁移和验收。

品牌预设在 JSON 的 `branding` 中独立记录；启用时记录 `hqzy-logomark-v2`、内置 SVG 哈希及两个实际入口，未启用时记录目标品牌。内置 SVG 是用户提供的品牌资产，不是 shadcn/Lucide 组件或开源字体；不要套用通用图标描边、颜色或拉伸其比例。分发时必须包含完整技能目录；图标按当前 `SKILL.md` 所在目录解析并复制到目标项目，不读取作者电脑路径。

该 JSON 是本技能定义的可移植主题数据，**不是 shadcn CLI preset、registry 或 components.json**。不要作为 CLI 参数直接传入。

间距、密度与尺寸有固定目标，但不是锁死高度或重排页面的命令。检查换行、点击区域、断点及虚拟化测量；不能保持行为时，只保留受影响局部几何并登记例外。品牌资产仅在上述预设的 favicon/控制台品牌入口定点接入；第三方品牌、用户作品/预览、编辑器内容、代码高亮、图表业务配色及打印/导出不做全局替换。保留主题切换方式、存储键和默认模式，不因 JSON 附带 dark 就增加暗色开关。

## 4. 分批迁移并立即验证

按依赖顺序推进：主题及基础展示 → 表单外观 → 菜单/浮层 → 页面集成。每批先覆盖代表性使用点，验证通过后完成该组件的其他调用点，再继续下一批；这不是停留在试点的理由。

- 优先改共享组件实现和样式，保留 props、ref、children、事件载荷、回调次数及顺序。业务层只做必要的导入或等价组合调整，不移动 hooks/effects/reducer 或重写业务回调。
- 显式保留 `type`、`name`、`value/defaultValue`、`checked/defaultChecked`、`disabled`、`readOnly`、`form`、`id`、`aria-*` 和有效测试定位；保持受控/非受控边界及重置行为。
- 不靠合成伪造的 DOM event 去适配不同回调。无法用薄适配层维持原契约时，保留原控件并主题化；避免双触发或把对象/数字 ID 隐式变成字符串。
- 保留触发动作、步骤数量、快捷键、焦点移动/返回、点击外部与 Escape 策略、modal/非 modal、portal、关闭后状态保留和滚动行为。
- 保留 loading、empty、error、disabled、hover、focus 和已有动效时机，尊重 reduced-motion。为已有状态补齐样式，不新增功能分支、确认流程或动画。
- 专用编辑器、拖拽、上传、虚拟表格、地图、图表及复杂日历通常保留引擎；仅把可定制外观映射到主题。不要用静态官方示例替换真实能力。
- 旧 UI 依赖仅在所有消费者都没有引用后移除；保留依赖的复杂控件不为了“清理干净”强行重写。

## 5. 验收、差异复查与交付

运行项目已有的 typecheck、lint、相关 tests 和生产 build，按实际脚本执行，不编造根级命令。对改变了交互适配的组件，复用/补足能观察行为的针对性回归；纯颜色/圆角改动不建立只匹配 class 的测试。

在可运行环境对照基线验证关键完整流程：提交/取消/重开、键盘、持久化、URL、错误状态和权限分支；请求次数及载荷不变。测试使用已有测试账号/数据，不触发真实支付、发送或不可逆操作。检查桌面、窄屏、长内容及原本支持的主题，检查控制台、hydration 和横向溢出。

依 [验收矩阵](references/acceptance.md) 检查字体真实加载、computed 样式、状态、对比度、尺寸、缩放、键盘和受影响断点。复查完整 diff 与迁移台账：业务模块、请求、事件、副作用和无关配置不得出现意外变化；搜索剩余旧样式/旧库及硬编码覆盖。引用搜索不能替代运行时验证，截图相似也不能证明行为等价。证据跟随项目约定存放，不提交敏感测试数据。

交付内容简洁而可核查：

1. 使用的主题 ID/版本、涉及的页面和共享组件；多项目分别说明。
2. 官方替换项与兼容保留项，注明具体原因，不隐瞒覆盖缺口。
3. 实际执行的命令、关键流程结果和入口前后截图位置（如果已采集）。
4. 既有失败、新发现的回归和未验证项分别列出。

有回归时继续修复 UI 适配；无法等价修复则只撤回本次相关替换，保留有效的外观统一。缺少运行环境时完成可独立进行的修改和静态检查，明确需要什么才能完成验收，不能宣称“已验证交互完全不变”。

## 调用示例

默认：`使用 $shadcn-ui-unify 统一当前 React 项目的 UI，只换视觉，不改变业务逻辑和交互。`

指定基线：`使用 $shadcn-ui-unify，将这些指定项目统一到项目 A 的现有主题，保留各自的功能和交互。`

仅评估：用户明确要求只评估时，输出组件映射、行为风险和验证计划，不安装依赖或修改项目。
